# Content Writing

Load [content-de-entropy](../content-de-entropy/SKILL.md) and read the [shared contract](references/semantic-contract.md) before writing. Both skills govern both skills and their supporting content as one workflow.

**Construct:** contract → visible structure → necessary words → de-entropy audit → delivery.

Make relationships visible in the representation itself instead of making the reader reconstruct them from prose. Choose structure from meaning, not decoration for an already-written paragraph.

## Encode directly

Choose the form whose visible relations match the relations being expressed:

| Meaning | Representation |
| --- | --- |
| Containment, grouping | Nesting, indentation, boundaries |
| Comparison on shared dimensions | Aligned rows and columns |
| Order, dependency, transition | Paths and directed links, labeled with the actual relation |
| Exact form | The form itself: template, notation, literal example |
| Reference to an existing object | A recognizable label pointing directly to that object |

Use established notation or define it at the point of use. Position, direction, grouping, and scale carry claims too: a bare arrow must not turn sequence into causation or possibility into certainty.

## Complete the representation

Keep qualifications attached to the elements they qualify. Use words for names, relation labels, and meaning that structure cannot carry precisely; preserve wording whose form itself carries required value.

Do not restate visually encoded information in prose unless the contract requires that restatement. Point to an existing authoritative object rather than re-create it, without making the reader recover missing meaning from an opaque or inaccessible reference.

Use forms supported by the destination. Rendering must preserve the intended relations; otherwise use simpler structure or the necessary words.

Before delivery or domain-specific validation, apply `content-de-entropy` to the draft. An unchanged draft is a valid outcome; reduction is not a quota.
